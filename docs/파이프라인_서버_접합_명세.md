# 파이프라인 ↔ 서버 접합 명세

작성일: 2026-08-20
대상: [geonoh-nam/StaryDot](https://github.com/geonoh-nam/StaryDot) `main` (`365f03a`)

## 0. 이 문서의 범위

**엔드포인트 설계는 [`docs/superpowers/specs/2026-08-19-video-subtitle-db-design.md`](superpowers/specs/2026-08-19-video-subtitle-db-design.md)가 이미 정했고, 그것이 상위 문서다.**
9개 엔드포인트, SQLite 스키마, CLI 인제스트, 앱 변경 순서가 거기 다 있다. 이 문서는
그것을 다시 쓰지 않는다.

여기서 다루는 것은 **한 군데뿐**이다.

```
server/tools/generate.js:38
  // ponytail: fixed schedule stands in for the analysis. Swap this block for the real generator.
```

그 자리에 `oneshot/` 파이썬 파이프라인이 들어간다. 지금 목 데이터가 내놓는 모양과
`oneshot`이 내놓는 모양이 달라서, 그대로 갈아끼우면 앱에서 깨진다. 이 문서는 그 둘을
잇는 계약이다.

## 1. 지금 무엇이 다른가

`generate.js`가 심는 quiz payload (`generate.js:23-36`):

```js
{
  title: '우아핑의 색깔은?',
  options: [
    { label: '노랑색', color: '#f0ae03', bg: '#fffaf0' },
    { label: '보라색', color: '#9b5de5', bg: '#f6f0ff' },
    { label: '하늘색', color: '#00CFE9', bg: '#f1fdff' },
    { label: '핑크색', color: '#e24e9e', bg: '#fff4fa' },
  ],
  answer: '하늘색',
}
```

`oneshot.check`가 내놓는 활동 (`oneshot/check.py:41`):

```json
{
  "timestamp_sec": 55.0,
  "activity_template": "감정_추론",
  "question": "지팡이에서 빛을 뿜어내는 이 캐릭터의 마음은 어떨까요?",
  "options": ["신나요", "슬퍼요", "화나요"],
  "answer": "신나요",
  "why_here": "...",
  "scene_description": "..."
}
```

| | oneshot | 앱·DB |
|---|---|---|
| 질문 | `question` | `title` |
| 선택지 | 문자열 3개 | 객체 배열 (`label`/`color`/`bg`) |
| 정답 | `answer` (문자열) | `answer` (문자열, `label`과 대조) |
| 유형 | `activity_template` (한글 16종) | 없음 |
| 시각 | `timestamp_sec` (실수) | `at_sec` (정수) |

선택지 개수는 문제가 아니다. 앱은 `quiz.options.map(...)`으로 그리므로(`App.js:2199`)
3개든 4개든 렌더링된다. `oneshot/validate.py`가 정확히 3개를 강제하니 3개로 간다.

## 2. 계약

### 2.1 `type`은 렌더 방식, 세부는 `payload`

DB 스키마가 이미 `type` + `payload` JSON이다(`db.js:32-38`). 그 구조를 그대로 쓴다.

| `type` | 앱 컴포넌트 | 내용 출처 |
|---|---|---|
| `quiz` | `QuizOverlay` (`App.js:2141`) | 파이프라인 |
| `trace` | `TraceOverlay` (`App.js:1978`) | 앱 자산 (`payload.imagePath`) |
| `puzzle` | `PuzzleScreen` (`Puzzle.js:73`) | 앱 자산 (`payload.imagePath`) |

**oneshot이 만드는 활동 16종은 전부 `type: "quiz"`다.** 카탈로그가 전부 3지선다 구조라
렌더링 방식이 하나다. `trace`·`puzzle`은 파이프라인에 대응물이 없고 `generate.js`가
지금처럼 별도로 심는다.

`activity_template`은 버리지 않고 `payload`에 보존한다. 어떤 교육적 의도의 문제였는지가
두 곳에서 필요하다 — 보호자 리포트, 그리고 맞춤형 가중치 계산
(`oneshot/plan_types.weights_from_history`가 `{activity_template, correct}` 기록을 받는다).

### 2.2 quiz payload

```json
{
  "activity_template": "감정_추론",
  "title": "지팡이에서 빛을 뿜어내는 이 캐릭터의 마음은 어떨까요?",
  "options": [
    { "label": "신나요", "color": "#f0ae03", "bg": "#fffaf0" },
    { "label": "슬퍼요", "color": "#9b5de5", "bg": "#f6f0ff" },
    { "label": "화나요", "color": "#00CFE9", "bg": "#f1fdff" }
  ],
  "answer": "신나요",
  "audioUrl": null,
  "scene_description": "캐릭터가 지팡이를 들고 빛을 뿜는다",
  "why_here": "직전 대사가 끝나고 표정이 크게 잡힌다"
}
```

`answer`는 `options[].label` 중 하나와 정확히 일치한다.

`scene_description`과 `why_here`는 앱이 쓰지 않는다. 활동이 왜 여기 있는지를 나중에
사람이 되짚기 위해 남긴다 — DB만 보고도 판단 근거를 알 수 있어야 한다.

`audioUrl`은 문제 읽어주기용이고 아직 없다(`App.js:163` 주석 "filled from the content DB
once questions are served from there"). `null`이면 앱은 소리 없이 글자만 보여준다.

### 2.3 색은 서버가 배정한다

`color`와 `bg`를 oneshot은 만들지 않는다. 만들게 하지도 않는다 — 파이프라인 스키마와
검증 가드, 93개 테스트를 화면 장식 때문에 고칠 이유가 없다.

`generate.js`가 팔레트를 돌려가며 배정한다.

```js
const PALETTE = [
  { color: '#f0ae03', bg: '#fffaf0' },
  { color: '#9b5de5', bg: '#f6f0ff' },
  { color: '#00CFE9', bg: '#f1fdff' },
  { color: '#e24e9e', bg: '#fff4fa' },
];
// options[i] ← PALETTE[i % PALETTE.length]
```

**예외가 하나 있다.** 색을 묻는 활동(`색_찾기`, 만 3-4세)에서는 색이 장식이 아니라
문제 자체다. 이 유형은 `label`이 곧 색 이름이므로 팔레트를 돌리면 안 되고, 색 이름 →
색상값 사전을 따로 둬야 한다. 만 5-6세에는 이 유형이 없으므로 지금 당장은 걸리지 않지만,
연령대를 넓히는 순간 터진다.

`meaning`과 `example`(`App.js:167`)은 정답 후 학습 화면에 쓰이는데, 지금은 채우지 않는다.
앱이 없을 때 건너뛰도록 처리해야 한다.

### 2.4 변환 표

`generate.js`가 수행한다.

| oneshot | → | DB |
|---|---|---|
| `timestamp_sec` | `Math.round()` | `at_sec` |
| (모든 활동) | 고정 | `type: "quiz"` |
| `question` | 그대로 | `payload.title` |
| `options[i]` (문자열) | `{label, ...PALETTE[i]}` | `payload.options[i]` |
| `answer` | 그대로 | `payload.answer` |
| `activity_template` | 그대로 | `payload.activity_template` |
| `scene_description`, `why_here` | 그대로 | `payload.*` |
| `rejections` | 저장 안 함 | — |

`rejections`는 프롬프트를 고칠 때 보는 파이프라인 진단 정보다. 앱에도 리포트에도 쓰이지
않으므로 DB에 넣지 않는다. `oneshot` 출력 파일에 그대로 남아 있다.

## 3. generate.js 교체

지금 서명은 `node server/tools/generate.js <video_id>`이고, 자막을 DB에서 읽어
활동을 심는다. oneshot은 **영상 파일**이 필요하다(프레임을 뽑아야 한다). DB의
`video.file_path`로 찾을 수 있으므로 서명은 바뀌지 않는다.

```
node server/tools/generate.js <video_id> [--age-range 5-6] [--target-count 5]
```

흐름:

1. `setVideoStatus(db, videoId, 'analyzing')` — 지금과 동일
2. `video.file_path`로 실제 영상 경로를 구한다 (`MEDIA_DIR` 기준)
3. `python3 -m oneshot.prep --video <경로> --out-dir <임시> --age-range ... --crop-bottom ...`
4. 활동 생성 — **여기가 갈린다. §4 참조**
5. `python3 -m oneshot.check --activities ... --meta ... --out ...`
6. 결과 JSON을 §2.4로 변환해 `replaceActivities(db, videoId, rows)`
7. `trace`·`puzzle` 항목을 규칙에 따라 끼워 넣는다 (지금은 20초·30초 고정)
8. `setVideoStatus(db, videoId, 'ready')`

`status`가 `ready`로 올라가야 `/library`에 나온다. 실패하면 `analyzing`에 머무르게
두어야 반쪽짜리가 아이에게 안 간다. **지금 코드에는 실패 시 status를 되돌리는 처리가
없다** — 3~6단계 어디서 죽어도 `analyzing`에 남으므로 결과적으로는 안전하지만,
의도된 것인지 확인이 필요하다.

`--crop-bottom`은 영상마다 다르다. 자막이 화면에 구워져 있으면 관찰자 격리가 깨진다
(tinyping 실측에서 하단에 자막이 박혀 있었다). 영상 등록 시 사람이 프레임을 한 장 보고
정하는 값이라, `video` 행에 컬럼을 하나 두거나 `ingest.js`에 플래그로 받아 저장해야 한다.
**지금은 저장할 곳이 없다.**

## 4. 활동 생성 — 두 경로 중 무엇을 쓸 것인가

`oneshot`은 활동 생성에 두 경로가 있고, 성질이 다르다.

| | API 경로 (`oneshot.run`) | 에이전트 경로 (`quiz-agents` 스킬) |
|---|---|---|
| 실행 | `python3 -m oneshot.run` | Claude Code에서 사람이 호출 |
| 자격 증명 | `ANTHROPIC_API_KEY` 필요 | 불필요 |
| 자동화 | `generate.js`에서 바로 호출 가능 | **불가능** |
| 검증 | 실제 엔드포인트에 붙어본 적 없음 | tinyping·whale_princess 실측 완료 |

**`generate.js`가 자동으로 부를 수 있는 것은 API 경로뿐이다.** 에이전트 경로는 서브
에이전트를 띄워야 해서 셸에서 못 돌린다.

그런데 지금 검증된 것은 에이전트 경로이고, API 경로는 실제 API에 한 번도 붙어본 적이
없다. 그래서 당분간은 이렇게 간다.

- **에이전트 경로로 활동을 만들어 파일로 받는다** (`out_agents/<video_id>/<video_id>_activities.json`)
- `generate.js`에 `--from-file <경로>` 옵션을 두어 그 파일을 읽어 DB에 심는다
- API 키가 생겨 API 경로가 검증되면 `generate.js`가 직접 호출하도록 바꾼다

`--from-file`은 임시 우회가 아니라 계속 쓸 값이 있다. 사람이 활동을 손으로 고친 뒤 다시
심는 경로가 되기 때문이다.

## 5. 앱에 남은 연결

상위 설계서 §"앱 변경"이 목록을 갖고 있다. 이 문서 관점에서 한 가지만 덧붙인다.

**`QuizOverlay`가 문제를 props로 받아야 한다.** 지금은 모듈 상수 `quiz`를 직접
참조한다(`App.js:162`, `App.js:2199`). `LIBRARY`나 `ACTIVITIES`를 API로 바꾸는 것만으로는
파이프라인이 만든 퀴즈가 화면에 닿지 않는다. 이 한 군데가 마지막 관문이다.

`options[].meaning`·`example`이 없을 때 학습 화면을 건너뛰는 처리도 함께 필요하다
(`App.js:435`).

## 6. 미해결

- **`색_찾기` 유형의 색상값.** §2.3. 만 3-4세를 열면 걸린다.
- **`crop_bottom` 값을 저장할 곳이 없다.** §3.
- **`trace`·`puzzle`을 어떤 규칙으로 끼울지.** 지금은 20·30초 고정이다. 퀴즈와 최소 간격을
  둬야 하는지, 영상 길이에 비례해야 하는지 정해지지 않았다.
- **`audioUrl`을 무엇이 채우는지.** 서버가 TTS를 미리 만들어 `media/`에 둘지, 앱이 즉석
  합성할지.
- **`result` 값의 집합을 서버가 강제하지 않는다.** `correct`/`wrong`/`skip` 오타 하나로
  리포트 집계가 조용히 틀어진다.
- **API 경로가 실제 엔드포인트에 붙어본 적이 없다.** §4. 요청 형태는 SDK 타입과 대조해
  확인했지만 실제 응답을 받아본 적은 없다.
