# 영상 퀴즈 — 역할 분할 에이전트 경로

만 3~7세 아이가 영상을 보다 멈추고 푸는 활동을 만든다. `oneshot/` 파이썬 모듈이 프레임 추출과
검증을 맡고, 생각이 필요한 네 단계만 서브에이전트가 한다. Anthropic API 키를 쓰지 않는다.

**매번 다른 결과가 나오는 것이 의도다.** 같은 영상을 다시 봐도 다른 퀴즈가 나와야 한다.
결과를 고정하려 애쓰지 말 것.

## 인자

`/quiz-agents <영상경로> <연령대> [주제] [개수]`

연령대는 `3-4`, `5-6`, `7` 중 하나. 개수 기본값 5. 인자가 없으면 사용자에게 묻는다.

## 0단계 — 작업 폴더 준비 (파이썬)

```bash
python3 -m oneshot.prep --video <영상> --out-dir out_agents/<video_id> \
  --age-range <연령대> --topic "<주제>" --target-count <개수>
```

**먼저 프레임에 자막이 구워져 있는지 확인한다.** 별도 SRT가 있어도 영상에 자막이 박혀
있는 경우가 흔하다. 박혀 있으면 관찰자를 자막에서 격리한다는 이 파이프라인의 전제가
무너진다 — tinyping 실측에서 하단에 "고고핑을 생각하는 빤 짝"이 픽셀로 박혀 있었다.

프레임을 한 장 뽑아 직접 열어 본다. 자막이 보이면 `--crop-bottom`으로 하단을 잘라낸다.
0.22가 출발점이고, **자른 뒤 다시 열어 확인한다** — 자막 위치는 프레임마다 달라서 한 비율로
다 잡히지 않는다. tinyping은 0.22로도 [05:15] 한 장이 남았다. 남은 프레임은 1.5단계에서
오염으로 기록하고 지점에서 제외한다.

`out_agents/<video_id>/`에 `frames/`, `subtitles.md`, `meta.json`이 생긴다.
`meta.json`의 `frames` 배열이 각 프레임의 경로·라벨·시각을 담는다. 이후 모든 단계가 이 파일을 본다.

자막이 0줄이거나 프레임이 0장이면 여기서 실패한다. 그 경우 다음 단계로 넘어가지 말고 사용자에게 알린다.

## 1단계 — 관찰자 (독립 2인, 병렬)

**같은 프레임을 두 명이 서로 모르게 본다.** 한 명이 자신 있게 틀리면 못 걸러내기 때문이다.
프레임이 20장을 넘으면 20장씩 묶고, 묶음마다 A·B 두 명을 띄운다. 72장이면 8명이다.
전부 동시에 띄운다.

**B에게 A의 기록을 보여주지 마라.** 보여주면 B가 A에 끌려가 대조가 무의미해진다.

**둘 다에게 자막을 주지 마라. 이게 이 설계의 핵심이다.** 자막을 같이 주면 모델은 화면을
대충 보고 자막으로 장면 설명을 지어낸다. 기존 파이프라인의 `scene_description`이 정확히
그렇게 망가졌다. 관찰자를 자막에서 격리해야 장면 기록이 화면에만 근거한 독립 기록이 되고,
4단계 검수자가 "이 문제 자막만 읽어도 풀리는데?"를 판정할 기준이 생긴다.

관찰자 지시(A·B 동일):

> 프레임 이미지를 Read 도구로 한 장씩 보고, 화면에 **실제로 보이는 것만** 적는다.
> 프레임당 한 줄, `[MM:SS] 설명` 형식. 등장 인물과 그 표정, 사물, 배경, 동작을 적는다.
> 이야기의 맥락이나 인물의 의도를 추측하지 마라 — 보이지 않는 것은 쓰지 않는다.
> 앞뒤 프레임을 근거로 "~하려는 중"이라고 쓰지 마라. 그 한 장에 있는 것만 쓴다.
> 화면에 글자가 있으면 따옴표로 그대로 옮긴다. 색과 개수는 셀 수 있으면 센다.
> 어둡거나 흐려서 판별이 안 되면 그렇게 쓴다. 지어내지 마라.

### 1.5단계 — 대조

A와 B의 기록을 프레임별로 맞춰 본다. 이 판정은 당신(오케스트레이터)이 직접 한다 —
에이전트를 하나 더 띄우지 마라. 판단 기준은 **핵심 요소가 일치하는가**다.
표현이 달라도 같은 것을 가리키면 합의로 본다. "은색 티아라"와 "머리에 쓴 왕관"은 합의,
"뱀 모양 형체"와 "고래 지느러미"는 불일치다.

두 파일을 쓴다.

- `out_agents/<video_id>/01_scenes.md` — 합의된 내용만. 프레임당 한 줄, 라벨 순서대로.
  둘이 각각 본 것 중 한쪽에만 있는 세부는 빼고, 겹치는 것만 남긴다.
- `out_agents/<video_id>/01_conflicts.md` — 엇갈린 프레임. 라벨, A의 서술, B의 서술,
  무엇이 엇갈렸는지. 한쪽이 "흐리다"고 한 프레임도 여기 넣는다.

불일치가 전체 프레임의 절반을 넘으면 멈추고 사용자에게 알린다. 프레임 품질이나
간격이 잘못됐다는 뜻이지, 더 진행할 일이 아니다.

## 2단계 — 지점 선정자

**먼저 넣을 수 있는 최대 개수를 계산한다.** 이걸 건너뛰면 뒤에서 대량으로 버려진다 —
whale_princess 첫 실행에서 후보 10곳 중 6곳이 간격 규칙에 걸려 버려졌고, 출제자와
검수자가 그 6곳에 들인 작업이 통째로 낭비됐다.

```bash
python3 -c "
from oneshot.plan_types import max_points
print(max_points(<duration_sec>, 20.0))
"
```

85초 영상이면 4곳이다. 목표 개수가 5개라도 4곳이 상한이다. 그 사실을 알고 시작한다.

입력: `subtitles.md`, `01_scenes.md`, `01_conflicts.md`, `meta.json`.
**프레임 이미지는 주지 않는다** — 1단계 기록이 그 역할이다. 정밀도가 필요한 판단은 3단계가 한다.

후보 개수는 **`min(상한, 목표 개수 × 2)`**다. 두 방향의 낭비를 다 막아야 한다.

- 상한을 넘겨 뽑으면 뒤에서 간격 규칙에 걸려 버려진다 (85초 영상에 10곳 → 6곳 폐기).
- 목표의 2배를 넘겨 뽑으면 애초에 쓸 데가 없다 (361초 영상, 목표 5개인데 후보 27곳).

85초·목표 5개면 `min(4, 10)` = 4곳. 361초·목표 5개면 `min(18, 10)` = 10곳.

지시:

> 자막과 장면 기록을 대조해 활동을 넣을 지점을 고른다.
>
> - **`01_conflicts.md`에 있는 프레임 근처는 피한다.** 관찰자 두 명이 다르게 본 화면은
>   애매한 화면이고, 애매한 화면은 퀴즈 지점으로 나쁘다. 피할 수 없으면 그 사실을 적는다.
> - 말이 끝나고 쉬는 곳에 넣는다. 대사 한가운데를 끊지 마라.
> - 지점끼리 최소 20초 떨어뜨린다. 이건 권고가 아니라 뒤에서 강제된다.
> - 그 지점까지 본 것만으로 풀 수 있어야 한다. 뒤에 나올 내용을 묻지 마라.
> - `why_here`에 "자연스럽게 연결되며" 같은 형식 문구를 쓰지 마라. 그 순간 화면과 자막에
>   무엇이 있어서 활동이 성립하는지를 적는다.

각 후보의 키: `timestamp_sec`, `why_here`, `nearby_frame_labels`, `subtitle_context`.
`out_agents/<video_id>/02_points.json`에 JSON 배열로 쓴다.

**기준에 안 맞아 버린 구간도 남긴다** — `out_agents/<video_id>/02_skipped.md`에
구간과 이유를 적는다. "흐려서 못 씀"이 몇 번 나오는지가 프레임 간격이나 추출 품질을
조정할 신호인데, 말로만 보고하면 그 신호가 사라진다.

## 2.5단계 — 유형 배정 (파이썬)

지점이 정해지면 **코드가 유형을 배정한다.** 프롬프트로 "다양하게 쓰세요"라고 부탁하면
모델은 만들기 쉬운 유형으로 기운다 — whale_princess 실측에서 9개 중 `그림과_낱말_연결`이
4개였고 `이야기_되새기기`는 0개였다.

```bash
python3 -c "
import json, sys
sys.path.insert(0, 'pipeline')
from schemas import templates_for_tier
from oneshot.plan_types import assign_types
points = json.load(open('out_agents/<video_id>/02_points.json'))
templates = list(templates_for_tier('<연령대>'))
for p, priority in zip(points, assign_types(len(points), templates)):
    print(p['timestamp_sec'], '→', ' > '.join(priority[:3]))
"
```

가중치를 주지 않으면 균등이다. 아이의 풀이 기록이 있으면 `weights_from_history(history, templates)`로
가중치를 만들어 `assign_types(n, templates, weights)`에 넘긴다 — 자주 틀린 유형이 더 자주 배정된다.

출력을 3단계 출제자에게 그대로 넘긴다. 1순위 하나가 아니라 **우선순위 목록**을 넘기는 것이
중요하다. 그래야 출제자가 "이 지점에서 1순위는 못 만든다"일 때 지점을 버리지 않고 다음으로 넘어간다.

## 3단계 — 출제자

입력: `02_points.json`, `subtitles.md`, 각 후보 지점 **근처 프레임의 실제 이미지**,
2.5단계가 배정한 **지점별 유형 우선순위**, 그리고 해당 연령 티어의 활동 카탈로그.

`01_scenes.md`는 주지 않는다. 그건 4단계 검수자가 쓸 독립 기준이라, 출제자가 베끼면
대조가 무의미해진다. 화면 정보가 필요하면 프레임을 직접 보게 한다.

카탈로그는 코드가 단일 출처다. 출제자에게 넘기기 전에 읽어서 프롬프트에 넣는다:

```bash
python3 -c "
import sys; sys.path.insert(0, 'pipeline')
from schemas import templates_for_tier
for n, d in templates_for_tier('<연령대>').items(): print(f'- {n}: {d}')
"
```

지시:

> 후보 지점마다 활동을 하나씩 만든다. 프레임을 직접 보고 만든다.
>
> - **지점마다 배정된 유형 우선순위를 따른다.** 1순위로 만들어 보고, 그 지점에서
>   1순위가 성립하지 않으면(예: 화면에 이름 붙일 사물이 없어 `빠진_글자_완성`을 못 만듦)
>   2순위, 3순위로 내려간다. 어느 것도 안 되면 그 지점을 버린다.
>   **배정을 무시하고 만들기 쉬운 유형으로 돌아가지 마라.** 그러면 배정이 무의미해진다.
> - `activity_template`은 위 카탈로그의 이름을 **그대로** 쓴다. 바꿔 쓰거나 지어내지 마라.
> - 선택지는 정확히 3개, 정답은 정확히 1개.
> - 정답의 근거가 화면이나 자막에 있어야 한다. 짐작해야 풀리면 그 지점은 버려라.
> - 선택지 3개는 같은 층위여야 한다. 장소를 묻는데 "하트로즈, 고고핑의 집, 야외"처럼
>   범주가 섞이면 안 된다.
> - 아이가 소리 내어 읽을 문장으로 쓴다.
> - 만들 수 없는 지점은 억지로 만들지 말고 건너뛴다. 개수를 채우는 것보다 버리는 게 낫다.

각 활동은 `timestamp_sec`, `activity_template`, `question`, `options`(3개), `answer`,
`why_here`, `scene_description` 키를 갖는다. `out_agents/<video_id>/03_activities.json`에 쓴다.

## 4단계 — 검수자

입력: `03_activities.json`, `subtitles.md`, `01_scenes.md`, `01_conflicts.md`, 해당 프레임 이미지.

**출제자와 다른 에이전트여야 한다.** 자기가 만든 문제를 스스로 검수하면 통과시킨다.

지시:

> 활동을 하나씩 원본과 대조한다. 각 항목에 대해 판정하고, 통과한 것만 남긴다.
>
> 1. 정답이 정말 하나뿐인가. 다른 선택지도 답이 될 수 있으면 버린다.
> 1-b. **오답이 그럴듯한가.** 오답이 이 영상과 무관한 것(다른 작품 이름, 엉뚱한 범주)이면
>    영상을 안 봐도 맞힌다. 오답은 "이 영상 안에서 있을 법하지만 틀린 것"이어야 한다.
>    whale_princess 첫 실행에서 '사랑의 하츄핑 / 아기 상어 / 뽀로로'가 이 검사 없이 통과했다.
> 2. 정답의 근거가 화면이나 자막에 실제로 있는가. 프레임을 직접 확인한다.
> 3. **자막만 읽고도 풀리는가.** `01_scenes.md`는 자막 없이 화면만 보고 쓴 기록이다.
>    그 기록의 정보가 정답에 필요 없다면, 이 문제는 영상을 볼 이유가 없는 문제다. 표시해 둔다.
> 4. 선택지 3개가 같은 층위인가.
> 5. 만 <연령대>세 아이가 읽고 이해할 문장인가.
>
> 고칠 수 있으면 고치고, 못 고치면 버린다. 버린 것은 사유와 함께 따로 적는다.

`out_agents/<video_id>/04_reviewed.json`에 통과한 활동 배열을 쓴다. 버린 것과 사유는
`out_agents/<video_id>/04_rejected.md`에 남긴다 — 프롬프트를 고칠 유일한 단서다.

## 5단계 — 결정론적 가드 (파이썬)

```bash
python3 -m oneshot.check \
  --activities out_agents/<video_id>/04_reviewed.json \
  --meta out_agents/<video_id>/meta.json \
  --out out_agents/<video_id>/<video_id>_activities.json
```

카탈로그 위반, 정답 누락, 선택지 중복, 영상 길이 밖, 발화 한가운데(가장 가까운 침묵으로 스냅),
최소 간격을 검사한다. 버려진 항목은 결과의 `rejections`에 사유와 함께 남는다.

활동 0개면 0이 아닌 코드로 끝난다. 그건 실패다 — 성공으로 보고하지 마라.

## 사용자에게 보고할 것

- 최종 활동 개수와 각각의 지점·유형·질문
- 4단계와 5단계에서 버려진 것과 그 사유
- 자막만으로 풀리는 문제가 몇 개였는지 (4단계 3번 판정) — 프레임이 실제로 기여했는지의 지표
- 관찰자 A·B가 엇갈린 프레임 수 — 프레임 품질의 지표
- 최종 활동의 유형 분포, 그리고 2.5단계 배정과 얼마나 달라졌는지 — 배정이 먹히는지의 지표
- 단계별 산출물이 `out_agents/<video_id>/`에 남아 있다는 것

## 하지 말 것

- 관찰자에게 자막 주기
- 관찰자 B에게 A의 기록 보여주기
- 출제자에게 `01_scenes.md` 주기
